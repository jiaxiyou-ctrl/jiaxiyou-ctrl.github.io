# 项目原理｜面向空间推理学习的交互式立方体搭建系统

## 1. 任务与学习目标

学生看到目标俯视图、正视图和右视图，在网页中搭出符合三个方向要求的结构。练习从位置与高度逐步进入遮挡和多解，重点是理解“结构改了哪里，哪个方向会看到变化”。

流程：**观察目标 → 虚拟搭建 → 比较差异 → 修改 → 提交并解释。**

底板固定为 3 × 3，每格连续堆叠 0–3 层。范围清楚使表示和结果能够完整验证。题目设计见[练习说明](EXERCISES.zh-CN.md)。

## 2. 用一份高度表表示搭建

每个数字记录一格的层数。数据从前向后、从左向右排列；屏幕的按格编辑器把后排放在上方。

```text
数据：                        屏幕：
[[2,1,0],  ← 前排             后排 0 0 1
 [0,1,2],                         0 1 2
 [0,0,1]]  ← 后排             前排 2 1 0
```

这个结构共七块。相同高度表同时驱动立体显示、三视图、方块计数、反馈与保存。旋转和缩放单独记录；观察角度改变时，结构和答案不变。

高度表适用于连续堆叠；若支持悬空和内部空洞，就需要逐个三维位置记录是否有方块。当前虚拟编辑只产生完整整数状态；旧输入适配器保留在代码中，但不参与学生工作台。

## 3. 从结构计算三个方向

| 视图 | 计算 | 上例结果 |
|---|---|---|
| 俯视 | 每格高度是否大于零 | 五格占据 |
| 正视 | 每列沿前后方向取最高层数 | 2、1、2 |
| 右视 | 每排沿左右方向取最高层数，按前→后显示 | 2、2、1 |

从前方或右侧观察时，高堆覆盖同一观察方向上低堆的轮廓，因此连续堆叠下可取最大值。这里保留单位方格边界，表示轮廓与占据关系，不画完整工程制图隐藏线。

答案检查比较三个视图，不能要求逐格复制参考结构。例如 [[2,1,0],[1,2,0],[0,0,0]] 与 [[1,2,0],[2,1,0],[0,0,0]] 的结构不同，三个视图却相同。当前第 1–5 题各一解，第 6–8 题分别有 2、5、7 解。

## 4. 一次点击怎样更新系统

**命中某一堆 → 区分点击与拖动 → 检查层数边界 → 保存修改前状态 → 改高度表 → 重画模型并重算三视图 → 更新反馈与本地存档。**

SVG 可点击表面带有行列坐标，点击任一可见面都修改该堆顶部。悬停预览不修改数据。移动超过五个屏幕像素即按拖动处理，拖回原点也不触发放置。鼠标释放才确认点击；取消与旋转工具不添加方块。

绘制模块计算顶点的屏幕位置，处理可见面、相邻面遮挡和前后顺序，保留小方块分隔边线。动画刷新调度连续旋转。被挡住的位置可打开透视编辑：实体面淡化并退出命中，九个底板格子在独立图层提供点击区域，点击仍修改对应堆的顶层。透视模式限制最低俯角，避免底板压成一条线。右键或 Shift 点击直接移除，拖动则只旋转。

撤销和重做保存结构快照。撤销后产生新编辑会清除旧的重做分支；恢复后重新计算所有显示。提交保存独立快照，重复结构不重复计数。切题和重新打开时按题恢复，存储失败有提示。

练习和示例使用不同会话：示例只在内存中修改，不读取或写入练习存档，也不提供提交。返回练习时恢复原来的状态。提示直接在当前三视图标出黄色差异格：加号表示缺少的投影，减号表示多出的投影。开启后随修改持续更新；当前正确结构已提交后才出现“想一想”。

## 5. 工具与模块选择

| 技术 | 在项目中做什么 |
|---|---|
| HTML / CSS | 中文教学工作台、工具、题目与对照布局 |
| JavaScript | 状态、投影、判题、反馈与持久化 |
| SVG | 根据数据绘制立体图和二维视图 |
| localStorage | 当前浏览器内的练习恢复 |
| Node.js | 提供本地网页文件，运行可重复测试 |

核心几何在 core.mjs，显示在 draw.mjs，手势在 scene.mjs，历史与存档在 workspace.mjs，模式隔离在 session-mode.mjs，解释条件在 feedback.mjs，页面协调在 app.mjs。没有模型训练过程；项目体现的是空间表示、任务约束、交互状态和验证设计。

## 6. 怎样验证和展示

计算验证使用手算例子与独立体素投影算法，对全部 4⁹ = 262,144 种允许结构逐项比较；操作规则检查边界、取消、历史、去重和恢复。当前 36 项检查通过，完整结果见 validation-report.json。

真实浏览器验证单独检查点击、拖动、遮挡、布局、提示和保存，见[操作检查记录](UI-CHECKS.md)。测试总耗时不能代表用户操作延迟。学生学习效果需要实际教学评价，尚无相应数据。

展示以当前实际界面、一次修改引起的视图变化、多解对照和验证方法为主。个人贡献按实际设计决定、亲手代码修改与检查过程整理，见[个人实践记录](PERSONAL-PRACTICE.zh-CN.md)。
